# Device verification

This document records how to run OFFLINE as a native development build, the exact commands used to produce the first verified simulator build, and the manual on-device checklist that must still be completed by a human with a physical iPhone.

## Why a development build (not Expo Go)

The app depends on `llama.rn`, a custom native inference module that Expo Go cannot load. A development build (`expo-dev-client`) is therefore required to run the app at all. There is no `ios/` or `android/` directory in the repository — both are generated by `expo prebuild` (Continuous Native Generation) and are gitignored. Never commit them.

## App configuration

Both identifiers are already set in `app.json` — no change was required:

- `ios.bundleIdentifier`: `com.bhuv2123.offline`
- `android.package`: `com.bhuv2123.offline`

## Commands used

```bash
# 1. Confirm dev-client aligns with SDK 57 (reported "up to date" — no version change)
npx expo install expo-dev-client

# 2. First-time CNG generation (regenerates ios/ + android/ from app.json and config plugins)
npx expo prebuild --clean

# 3. Build, install, and launch on the simulator
npx expo run:ios --device "iPhone 17 Pro"

# 4. Dev server (Metro) — started automatically by `expo run:ios`; can also be run standalone:
npx expo start
```

## Build result (2026-10-07 — first verified simulator build)

- `npx expo prebuild --clean` regenerated `ios/` + `android/` and installed CocoaPods — no app-config change was required (both identifiers already set).
- `npx expo run:ios --device "iPhone 17 Pro"` → **Build Succeeded, 0 errors, 1 warning** (warning detail not captured in the expo log).
- App installed on the booted iPhone 17 Pro simulator as `com.bhuv2123.offline` (v1.0.0) and launched.
- Metro started automatically on `http://localhost:8081`; JS bundle served in 564 ms (1357 modules, `node_modules/expo-router/entry.js`).
- The app process was confirmed running on the simulator (`UIKitApplication:com.bhuv2123.offline`); the home screen (with `react-native-maps` preview) rendered — the `default.csv` and `CAMetalLayer` log lines are benign simulator/RN noise.
- After verification the Metro server started by `expo run:ios` was stopped (do not leave dev servers running). Start it again with `npx expo start` when the app is opened from the dev-client launcher.

## Physical device: the same command

For a physical iPhone (not available in this environment):

```bash
npx expo run:ios --device
```

and for Android once the SDK is installed:

```bash
npx expo run:android
```

A physical device session is required to verify real GPS, device text-to-speech, and haptics (see checklist below). Simulator checks confirm the native build, launch, and app startup only.

## Manual device checklist

Per the OFFLINE demo requirements (`OFFLINE.md` §33 and the MVP loop). The full walkthrough requires a human outdoors with a physical iPhone; the simulator can only cover the first two rows.

| # | Step | What to verify | Status |
|---|---|---|---|
| 1 | **Prepare** | Enter available time; local planner builds the experience (route, landmarks, missions, attention budget) | ✅ Simulator |
| 2 | **Briefing** | Read the short plan aloud; keep it concise (screen is the last resort) | ✅ Simulator |
| 3 | **Start** | Start the walk; phone goes into the pocket / away from the hands | 🔒 Human on device |
| 4 | **Phone away** | App runs in the background with screen off; no mid-walk UI is required | 🔒 Human on device |
| 5 | **Cues / haptics** | Occasional spoken cues and haptic taps at meaningful moments (turn, off-route, recovery, mission pacing); no map-following | 🔒 Human on device — needs real GPS + TTS + haptics |
| 6 | **Return** | Walk completes; session recorded locally (SQLite) | 🔒 Human on device |
| 7 | **Story report** | Screen returns with the story report: outdoor time, route completion, missions noticed, DIS / PES / ADR | ✅ Simulator (can be exercised end-to-end) |
| 8 | **Archive / export** | "Past walks" lists sessions; Export produces valid JSON; Delete works after confirmation | ✅ Simulator (to be exercised) |

Legend:

- ✅ — verifiable on the iOS simulator in this environment (no sensors/voice needed).
- 🔒 — BLOCKED in this environment; requires a human on a physical device (GPS, microphone-free TTS, haptics, background behavior with screen off). These items stay human-in-the-loop until the next device session.

## Notes and known limitations

- The simulator cannot attest to GPS accuracy, background audio, haptic feel, or battery behavior — those are the blocked rows above.
- The default provider is the deterministic `MockModel` (`src/config/integrations.ts`); it needs no network and no model download.
- Switching to the TinyLlama provider downloads the pinned GGUF to the app's private document directory on first use (size-validated). See `docs/integrations.md`.
- `npx expo prebuild --clean` wipes and regenerates the native directories. The regenerated iOS/Android projects no longer bundle any model weight file — consistent with the documented design that the model is never bundled into the native application.
